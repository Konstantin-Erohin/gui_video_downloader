# Video Downloader — Tkinter + yt-dlp

Простое локальное приложение для Windows и macOS для скачивания видео. Нужен Python **3.10+** или выше.

## Возможности

Вставьте URL → «Получить качества» → выберите максимальную высоту → выберите папку
→ «Скачать». И получение информации, и скачивание выполняются в отдельном потоке.
Tkinter получает события через очередь; фоновые потоки не обращаются к виджетам.

Сохранён фильтр исходного кода:

```text
bestvideo[height<=HEIGHT]+bestaudio/best[height<=HEIGHT]
```

Выбранная высота — верхняя граница: если нужного формата нет, возможен более низкий.
Резерв `best` выбирается, когда нет подходящей пары отдельных потоков; это не повтор
скачивания после сетевой ошибки. Список содержит уникальные высоты видеоформатов.

FFmpeg объединяет отдельные дорожки без перекодирования в MKV, совместимый с разными
кодеками. Если скачан готовый формат с видео и аудио, сохраняется исходный контейнер.
Имя: `Название [id].ext`. Существующие файлы не перезаписываются; `.part` позволяет
yt-dlp продолжать незавершённую загрузку при повторной попытке.

Прогресс относится к **текущему потоку**, поэтому может начинаться заново для аудио.
Если размер неизвестен или идёт объединение, показывается движущийся индикатор.
«Готово» появляется после завершения yt-dlp, включая постобработку. Во время работы
элементы управления заблокированы, закрытие окна просит дождаться завершения.
Отмена и очереди загрузок не реализованы. Плейлисты и текущие прямые эфиры отклоняются;
ссылка на отдельное видео с параметрами плейлиста скачивает одно видео.

## Структура

```text
app.py                  окно и обработка событий
downloader.py           работа с yt-dlp и поиск FFmpeg
build.py                локальная сборка PyInstaller
requirements.txt        зависимости приложения
requirements-build.txt  зависимости сборки
bin/                    FFmpeg, ffprobe, необязательно Deno
tests/test_downloader.py  автономные проверки логики
```

## Запуск на macOS

В рабочем окружении проекта используется Homebrew Python 3.12 и `.venv`.
Tkinter устанавливается для базового Python, а не через pip внутри venv:

```bash
brew install python-tk@3.12
```

После установки Tkinter уже созданное окружение пересоздавать не потребовалось.
Проверка из папки проекта: `.venv/bin/python -m tkinter`.
Если `.venv` уже существует, пропустите команду его создания ниже.


Установите Python с Tkinter, например установщиком с https://www.python.org/downloads/macos/.
Проверьте `python3 -m tkinter`: должно открыться тестовое окно. Для Homebrew Python
нужен соответствующий пакет Tk, например `python-tk@3.12` для Python 3.12.

```bash
cd ~/projects/tk_downloader
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
python -m pip install -U -r requirements.txt
python app.py
```

Если Python установлен как `python3.12`, используйте его вместо `python3` при создании
окружения. Системный Python 3.9 не подходит актуальному yt-dlp.

## Запуск на Windows (PowerShell)

Установите Python x64 с https://www.python.org/downloads/windows/, включая Tcl/Tk.
Откройте PowerShell в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -U -r requirements.txt
.\.venv\Scripts\python.exe -m tkinter
.\.venv\Scripts\python.exe app.py
```

Активация окружения не обязательна. Если установлены разные архитектуры Python,
создавайте окружение полным путём к нужному `python.exe`.

## FFmpeg и YouTube

Для скачивания нужны **ffmpeg и ffprobe**: положите бинарники в `bin/` (см.
[bin/README.md](bin/README.md)) или добавьте оба в PATH. Приложение сначала ищет
встроенные файлы, затем PATH. Python-пакет `ffmpeg` не заменяет эти программы.

Актуальный yt-dlp рекомендует JavaScript runtime для полноценной поддержки YouTube.
`yt-dlp[default]` устанавливает пакет `yt-dlp-ejs`; отдельно установите Deno в PATH
либо положите `deno` / `deno.exe` в `bin/`. При сборке локальный Deno включается
автоматически. Без него часть YouTube-форматов может быть недоступна. Предупреждения
показываются в окне, а не скрываются через `no_warnings`.

## Как были собраны FFmpeg и ffprobe для этого проекта

Использован **официальный исходный код FFmpeg**, скачанный пользователем со страницы
[FFmpeg — Download](https://ffmpeg.org/download.html#build-mac).
В проект был помещён архив **`ffmpeg-9.0.2.tar.xz`**. Сама команда FFmpeg распространяет
исходники; готовые сборки по ссылкам на странице загрузки выпускают сторонние авторы.
Оба инструмента — `ffmpeg` и `ffprobe` — собираются из одного архива.

Пользователь распаковал архив на Mac с Apple Silicon и выполнил в папке исходников
**`./configure`**, затем **`make -j4`**, без дополнительных параметров конфигурации.
Сборка заняла около пяти минут на его компьютере. Полученные бинарники были перенесены
в `bin/` проекта, после чего пользователь собрал приложение и подтвердил его работу.
Установленный ранее FFmpeg из Homebrew для этой сборки не копировался.

Последовательность для повторения (из папки проекта):

```bash
cd ~/projects/tk_downloader
tar -xf ffmpeg-9.0.2.tar.xz
cd ffmpeg-9.0.2
./configure
make -j4
```

Для компиляции нужны инструменты Apple Command Line Tools. На использованном Mac они
уже были установлены. Если компилятор отсутствует, установите их командой
`xcode-select --install` и дождитесь окончания установки.

Проверка готовых программ и копирование в проект:

```bash
./ffmpeg -version
./ffprobe -version
cd ..
mkdir -p bin
cp ffmpeg-9.0.2/ffmpeg bin/ffmpeg
cp ffmpeg-9.0.2/ffprobe bin/ffprobe
chmod +x bin/ffmpeg bin/ffprobe
```

Эти команды копирования предназначены для первоначального размещения или обновления
бинарников; существующие одноимённые файлы будут заменены. Если в `bin/` ещё лежат
старые скачанные сборки, сначала переместите их в другую папку.
`bin/` здесь — **папка внутри проекта**, а не системный `/bin`.

### Что делают команды сборки

- `./configure` проверяет ОС, архитектуру, компилятор и доступные библиотеки, затем
  создаёт конфигурацию для Makefile. Без неё свежераспакованные исходники ещё не готовы к `make`.
- `make -j4` компилирует и связывает исходники, выполняя до четырёх заданий одновременно.
  При повторном запуске использует готовые промежуточные файлы. Повторять `configure`
  перед каждым запуском `make` не требуется.
- `make install` копирует результат в место установки, заданное настройками сборки
  (например, через `./configure --prefix=...`). **В этом проекте эта команда не использовалась:**
  нужные два файла были вручную перенесены в `bin/`.

Обычный `./configure` выбирает настройки с учётом текущего окружения. Эта сборка не
объявляется полностью независимой от внешних библиотек без проверки. Посмотреть
зависимости можно так:

```bash
otool -L bin/ffmpeg
otool -L bin/ffprobe
```

Архив исходников полезно сохранить вместе со сведениями о версии и лицензиях.
Проверка криптографической подписи архива в этой сессии не выполнялась; порядок
проверки опубликован на [странице FFmpeg](https://ffmpeg.org/download.html#release-verification).

## Локальная сборка с FFmpeg внутри

Собирать нужно **на целевой ОС**: Windows EXE — на Windows; macOS APP — на macOS.
Подготовьте `bin/ffmpeg[.exe]` и `bin/ffprobe[.exe]` для той же архитектуры, что Python.
Сборщик проверяет наличие и запуск этих файлов. Он не скачивает их автоматически.

macOS — после размещения самостоятельно собранных FFmpeg и ffprobe в `bin/`:

```bash
cd ~/projects/tk_downloader
source .venv/bin/activate
python -m pip install -U -r requirements-build.txt
chmod +x bin/ffmpeg bin/ffprobe bin/deno
python build.py
```

Результат для Apple Silicon: `dist/VideoDownloader-macOS-arm64.app`.
Пользователь подтвердил, что эта macOS-сборка работает на его Mac. Сборка Windows
и проверка на другом Mac в рамках этой работы не выполнялись.

Для Intel Python: `dist/VideoDownloader-macOS-x64.app`. Для распространения передавайте
весь `.app`. Используется onedir-сборка. Автоматическая подпись сертификатом Developer ID
и notarization не настроены.

Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -U -r requirements-build.txt
.\.venv\Scripts\python.exe build.py
```

Результат при x64 Python: `dist/VideoDownloader-Windows-x64.exe`. Это onefile-сборка:
Python, библиотеки, FFmpeg и ffprobe упакованы в EXE и распаковываются во временную
папку при запуске. Отдельная установка Python и FFmpeg получателю не требуется.

На Mac с Windows ARM64 в UTM для целевого x64 EXE используйте **Windows x64 Python**
под эмуляцией и **Windows x64 FFmpeg/ffprobe**. ARM64-сборка не предназначена для
обычной Windows Intel/AMD. Проверяйте итоговый x64 EXE на реальном x64 Windows,
а macOS APP — на Mac целевой архитектуры без установленного FFmpeg.

Для переносимого macOS приложения используйте автономные FFmpeg/ffprobe и проверьте
их зависимости (`otool -L bin/ffmpeg`, аналогично ffprobe). Homebrew-бинарники могут
зависеть от библиотек локальной установки; успешная сборка не заменяет проверку
на чистой машине. Перед распространением приложите лицензии включённых компонентов.

## Состав репозитория

В Git хранятся исходники приложения, тесты, документация и файлы зависимостей.
Бинарники FFmpeg/ffprobe и Deno нужно подготовить локально по инструкциям выше:
в репозиторий они не включены. `.venv/`, `build/`, `dist/`, файлы `.spec`, кэши Python,
архивы и распакованные исходники FFmpeg исключены через `.gitignore`.

Для разработки создайте собственное `.venv`. Готовое приложение после сборки
находится в `dist/`; оно не требуется для работы с исходниками репозитория.

## Проверки и обновление

```bash
python -m compileall -q app.py downloader.py build.py tests
python -m unittest discover -s tests -v
python -m pip install -U -r requirements.txt
```

Проверки не скачивают внешние видео. Ручная проверка: открыть окно, получить качества
публичного видео, выбрать папку с пробелами, скачать и проверить изображение и звук.
Также проверить неверный URL, отсутствие FFmpeg и недоступное видео. После обновления
yt-dlp пересоберите приложение. Зависимости намеренно не закреплены до точной версии,
поскольку поддержка сайтов меняется; для воспроизводимой сборки сохраните
`python -m pip freeze > requirements-lock.txt` после успешной проверки.

При ошибках сайта сначала обновите yt-dlp. Видео, требующие входа или недоступные по
региону, могут не скачиваться: cookies и авторизация в интерфейсе не предусмотрены.

Документация: [yt-dlp](https://github.com/yt-dlp/yt-dlp),
[PyInstaller: сборка](https://pyinstaller.org/en/stable/usage.html),
[расположение встроенных файлов](https://pyinstaller.org/en/stable/runtime-information.html),
[FFmpeg](https://ffmpeg.org/download.html).
